What is Full Stack Development?

Full-stack development refers to building the front end and back end of a web application. Both parts are needed in order to develop the complete web application.

The front end refers to all user interface components, including buttons, forms, and other UI elements. This part is developed in HTML, CSS, and JavaScript. On the other hand, the back end involves the server component and deals with processes such as user authentication and storage of data. Back-end languages include Python and PHP. In addition, there is a need for a database which will be used to store data. Database technologies include MongoDB and MySQL.

Communication between these two components is established via API (application programming interface). Here, requests are made via HTTP methods including GET, POST, PUT, and DELETE.

Real-world example: Once you access the food delivery app interface (front end), you pick the food item and click on “Order Now.” The order information is relayed to the server via an API. On the back end, availability of the restaurants is verified, the order is stored in the database, and finally, the order request is placed at the restaurant.

The Three Layers

  • 🌐 Front End — HTML, CSS, JavaScript. What users see and touch.
    The front end refers to all the visible components displayed in the browser, including the visual design, colour scheme, navigation buttons, and transitions. The user interacts with the website through the buttons and forms by clicking on them.
  • ⚙️ Back End — Server-side logic and security (Node.js, Python, PHP).
    The back end acts as the engine behind the scenes of a website. It operates in a server (highly powerful computer), where tasks such as logging in your password or payment processes are handled. The users will never be able to access it; they just see its output.
  • 🗄️ Database — Where data lives (MySQL, MongoDB, PostgreSQL).
    The database serves as an organised filing cabinet of gigantic size. All data such as user names, messages, orders, etc., are stored in it, and the back-end accesses it as and when required. In its absence, any website will forget everything as soon as it is closed.

After learning this module, I will say that full stack is both interesting and difficult. The thing that intrigues me the most about it is the process of creation from scratch, turning my ideas into a working site.

HTML — The Structure

HTML stands for HyperText Markup Language and is one of the languages used in the design and structuring of web pages. Tags play an integral part in HTML as they help in arranging data by informing the browser how data, such as texts and images, should be displayed.

HTML5 introduced semantic tags like <header>, <nav>, <main>, and <footer>. These tell browsers and screen readers what the content is, not just how to display it. This matters for accessibility and SEO. Attributes like href, src, class, and id add extra information to elements.

Semantic Tags I Used

  • <header> — top section of the page
    What it is: The <header> tag surrounds the top portion of a page or a segment, typically consisting of your logo, site title, or main heading. Importance of Tag: This element signals to browsers and screen readers that they have reached the introductory region.
  • <nav> — navigation menu
    What it is: The <nav> tag encloses your navigation items, such as the navigation bar across the top of this webpage. The reason it is important is that it allows screen reader technology to direct users directly to the navigation section.
  • <main> — the primary content area
    What it is: The <main> tag encloses the actual content of the web page that makes each page unique. Importance: Instructs browsers to disregard other tags such as the sidebar and header tags and jump directly to the actual content of the page. SEO-friendly.
  • <article> — standalone content like a blog post
    What it is: The <article> tag is meant to contain self-standing content that stands alone as its own — such as news articles, blogs, or even product cards. Significance: Search engines will take it as standalone content, thus improving indexing and sharing.
  • <footer> — bottom of the page
    What it is: The <footer> tag encompasses content that stands alone and has meaning by itself, such as a news article, blog entry, or product card. Importance: This is considered independent content by search engines, enhancing indexing and distribution potential.
✅ What I learned: Semantic HTML is coding that is easy for people and software to understand.
⚠️ Challenge I faced: I kept using <div> for everything at first. Learning when to use semantic tags instead took some practice.

CSS — The Style

CSS (Cascading Style Sheets) is the style sheet language that allows you to define how a web page written in HTML will look. CSS enables styling HTML elements by setting color, font, margins, positions, and other options that make websites beautiful.

CSS works by selecting an HTML element and applying styles to it. You can select by tag (h1), by class (.button), or by ID (#header). The "cascading" part means styles can be overridden — more specific rules win. 

/* Selectors and properties */
h1 {
  color: #0f1c2e;
  font-size: 2rem;
}

.button {
  background: #4f9cf9;
  padding: 10px 20px;
  border-radius: 8px;
  transition: transform 0.2s;
}

.button:hover {
  transform: translateY(-2px);
}

/* Media query for phones */
@media (max-width: 700px) {
  h1 { font-size: 1.5rem; }
}

Key CSS concepts I learned:

  • Box Model — every element has margin, border, padding, and content
  • Flexbox — for arranging items in rows or columns easily
  • CSS Grid — for complex two-dimensional layouts
  • Media Queries — make websites responsive on phones and tablets
  • Transitions — smooth animations on hover states
✅ What I learned: The use of CSS variables (--blue: #4f9cf9) allows one to easily change colors throughout the entire site at once.
⚠️ Challenge I faced: I used to find it difficult to center website elements. But flexbox came along to help center things with display: flex; justify-content: center; align-items: center;.

Bootstrap — The Framework

Bootstrap is an open-source CSS framework that promotes simplicity and efficiency in web designing. It contains some templates for design that can be modified using HTML and CSS to change the font, forms, buttons, tables, navigation, dropdowns, and much more.

Bootstrap's 12-column grid is its most powerful feature. You divide your layout into columns using classes like col-6 (half width) or col-md-4 (one third on medium screens). The md part means the layout adjusts based on screen size — that's how responsive design works.

Why use a framework like Bootstrap? Think of constructing a home. You have two options: one, build each and every brick yourself; two, purchase ready-to-use bricks, and concentrate on designing. With Bootstrap, you have ready-made bricks that are already constructed for you, which saves you a lot of effort in coding, as you can focus on other aspects of development rather than spending time writing CSS again and again. 
<div class="container">
  <div class="row g-3">
    <div class="col-md-4">
      Card 1
    </div>
    <div class="col-md-4">
      Card 2
    </div>
    <div class="col-md-4">
      Card 3
    </div>
  </div>
</div>

<!-- Bootstrap button classes -->
<button class="btn btn-primary">
  Click me
</button>
What this code is doing, line by line:

.container — Wrapper with centered class that provides padding around to prevent the content from touching the screen borders.

.row — Creates a row horizontally. Columns have to be placed within a row, otherwise, the grid will collapse. g-3 adds a gap between columns.

.col-md-4 — Bootstrap divides a row into 12 columns. col-md-4 means "take up 4 out of 12 columns" — that's one third of the width. Three of these add up to 12, so all three cards sit side by side. The md means this layout only kicks in on medium screens and above; on a phone they stack vertically.

.btn .btn-primary — Bootstrap's ready-made button style. btn-primary applies the blue colour theme automatically — no CSS needed.
✅ What I learned: Bootstrap's breakpoints (sm, md, lg) let you control layout at different screen sizes without writing your own media queries.
⚠️ Challenge I faced: At first I didn't understand why columns needed to be inside a .row inside a .container — but that structure is what makes the grid system work correctly.

JavaScript — The Behaviour

JavaScript brings web pages to life. It lets you respond to user actions, update content dynamically, validate forms, and even save data — all without reloading the page.

How JavaScript Actually Works

Think of your HTML as a static blueprint and JavaScript as the person who can actually change things in that blueprint while someone is looking at it. Here are the core ideas:

🌳 The DOM — Your Page as a Tree

When a browser loads your HTML, it turns it into a tree of objects called the DOM (Document Object Model). Every tag becomes a node in that tree. JavaScript can reach into that tree and change anything — text, colour, visibility — at any time using document.getElementById() or similar.

👂 Events — Listening for Actions

JavaScript watches for things the user does — clicking a button, pressing a key, moving a mouse. These are called events. You attach a function to an event using onclick or addEventListener(). When the event fires, your function runs and something changes on the page.

🔁 Functions — Reusable Instructions

A function is a named block of code you can run whenever you need it. Instead of writing the same logic 10 times, you write it once as a function and call it by name. Functions can receive data (parameters) and return a result — like a machine: put something in, get something out.

🌐 fetch() — Talking to a Server

fetch() lets your page send a request to a server and receive data back — without refreshing the page. The server sends back JSON (a text format that looks like a JavaScript object). You then read that data and update the DOM with it. This is how live search, weather apps, and news feeds work.

// Event listeners + DOM manipulation
let count = 0;

function increase() {
  count++;
  document.getElementById("counter")
    .innerHTML = count;
  // finds the element with id="counter"
  // and changes its text to the new count
}

// Fetching data from an API
fetch("https://api.example.com/user")
  .then(res => res.json())
  .then(data => {
    console.log(data.name);
  });

// Saving to localStorage
localStorage.setItem("note", "Hello!");
let saved = localStorage.getItem("note");

What JavaScript can do:

  • Respond to events — clicks, typing, form submits
  • Change HTML and CSS on the fly (DOM manipulation)
  • Validate form inputs before submitting
  • Fetch live data from APIs using fetch()
  • Remember data between sessions with localStorage
✅ What I learned: JavaScript is what separates a static page from an actual app. Even small things like real-time form feedback make a huge difference to the user experience.
⚠️ Challenge I faced: Understanding how localStorage works took me a while — data is saved as strings, so you need JSON.stringify() and JSON.parse() to store objects.
